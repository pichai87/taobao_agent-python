# 第 2 课：单节点模型调用与结构化输出

> 阶段 4 整合后：本课是开发过程记录。旧单节点代码和测试分别保存在 `docs/learning/archive/02_minimal_agent.py`、`02_test_minimal_agent.py`，供回顾当时的实现；它们不属于当前运行包或测试套件。现在 `taobao-agent` 运行 `workflow.py` 中的 Intent → Supervisor 主流程。

## 1. 本阶段解决的问题

把用户问题送入一个 LangGraph 节点，节点调用一次 LLM，并将 JSON 回答校验成固定结构。这是后续 Intent Agent 与 Supervisor 的最短可运行前身，不处理实际取数。

## 2. 在整体 Agent 架构中的位置

原文采用 LangGraph 编排多 Agent、LangChain 运行 ReAct 专家。本课只用 LangGraph 的单节点图验证输入、状态传递和返回；尚未建立专家或 ReAct 工具循环。默认模型选用原文的通义系列轻量模型 `qwen-turbo`。

## 4. 调用链与数据流

```text
CLI 问题字符串
  → main() 读取环境变量并创建模型
  → run_once(question, model)
  → build_graph(model).invoke({"question": ...})
  → START → answer_node(MinimalState) → END
  → model.invoke([SystemMessage, HumanMessage]) 仅一次
  → JSON 字符串 → MinimalReply.model_validate_json()
  → 节点返回 {"reply": {"answer": ...}}
  → run_once() 返回 MinimalReply → CLI 输出 JSON
```

`MinimalState.question` 是用户输入，`reply` 是节点写回的状态更新。`MinimalReply` 是对外返回值，不等于会话记忆；当前没有 `MessagesState`、历史消息或工具结果。节点调用失败或 JSON 无效时不会伪造答案。模型限流异常沿图调用链传到 CLI 后，`main()` 将它转成简短提示和退出码 3。

## 5. 关键代码的执行过程

`build_graph()` 注册唯一的 `answer` 节点并连接两条边。节点将固定 System Message 与当前问题组成模型输入，调用 `invoke()` 一次。通义适配器绑定 `response_format={"type":"json_object"}`；这保证 JSON 语法的远端请求模式，但本地仍由 Pydantic 要求只有非空 `answer` 字段。`max_retries=0` 避免适配器在失败时悄悄重发模型请求。`run_once()` 在进图前拒绝空问题。

真实试运行中，`qwen-turbo` 返回了 HTTP 429、`limit_requests`。这表明请求到达百炼，但没有获得模型回答。CLI 只在输出边界捕获 `ModelRateLimitError`，不会在节点中改写 State，也不会自动重试或换用另一个 Key。运行时 `DASHSCOPE_API_KEY` 只接收当前命令选择的一个 Key；`DASHSCOPE_MODEL` 决定调用 Turbo 或 Plus。

## 6. 设计原因与替代方案

- **原文要求**：通义模型、LangGraph 多 Agent 与后续 LangChain ReAct。本阶段只取其中必要的图与模型调用能力。
- **必要工程补充**：百炼兼容接口通过 `langchain-openai` 接入，密钥由环境变量提供；模型作为参数注入，便于无密钥验证。当前只输出 `answer`，意图和参数留给阶段 3。
- **替代方案**：现在使用 `create_agent` 会提前引入 ReAct 循环；直接调用模型则无法验证 LangGraph State 流。当前图最小，后续可以在已测链路上增加节点。
- **依赖源**：官方 PyPI 文件站点超时后，使用清华 PyPI 镜像安装。uv 将镜像记录为项目默认索引和锁文件来源；该设置属于依赖获取配置，不是原文架构要求。
- **本次必要补充**：模型限流是外部服务失败，CLI 用退出码 3 明确报告。保持一次请求、零自动重试，方便学习阶段追踪真实调用次数。完整的重试策略留待 Harness 阶段根据业务需求设计。

## 7. 实际测试结果与限制

执行 `UV_CACHE_DIR=/private/tmp/taobao-agent-uv-cache uv run --offline python -m unittest discover -s tests -v`：7 个测试通过，退出码 0。其中 5 个是本阶段测试，另 2 个是阶段 1 环境测试。随后执行 `uv sync --locked --offline` 与 `uv run --locked --offline python -m unittest discover -s tests -v`，均退出码 0，7 个测试再次通过；这些命令都使用同一个临时 `UV_CACHE_DIR`。假模型验证了一次调用、两条输入消息、返回结构、非法 JSON、额外字段、空问题和缺密钥行为。CLI 在无密钥时退出码 2；用占位密钥构建模型对象成功，但未发请求。

用户在自己的终端配置了两个 Key，并用 Turbo Key + `qwen-turbo` 发起一次真实调用，百炼返回 `429 limit_requests`，因此**尚未验证成功的真实 LLM 回答**。根据[百炼错误码说明](https://help.aliyun.com/zh/model-studio/error-code/)与[限流说明](https://help.aliyun.com/zh/model-studio/rate-limit)，这类错误归于请求频率限制；稍后可单次重试并查看控制台模型监控。Plus Key + `qwen-plus` 尚未试运行，远端输出兼容性、延迟和费用仍未知。

针对本次错误，执行 `UV_CACHE_DIR=/private/tmp/taobao-agent-uv-cache uv run --locked --offline python -m unittest discover -s tests -v`：8 个测试通过，退出码 0。新增测试在 CLI 边界模拟限流，验证退出码 3、有提示、无堆栈；它不证明百炼限流已解除。项目当前不是 Git 仓库，未进行提交。

## 8. 上下文工程、通信协议与评估

第九章的起点是输入边界：System Message 放稳定的行为约束，Human Message 放当前问题；只传必要内容，避免模型把尚不存在的数据能力当作事实。第十章的外部工具协议尚不需要；本阶段是同进程模型调用。第十二章对应的验证是可确定的代码行为测试和一次失败的远端集成试运行，**不是**意图准确率、业务评测或 LLM Judge。429 测试只检查错误呈现，不代表服务可用。

## 9. Agent 岗位面试知识点

以下为常见技术知识点，并非引用公开面经：State 与模型消息的职责区别；为何要在模型 JSON 输出后再做本地类型校验；如何用依赖注入隔离外部模型；为何禁用隐式重试以核对调用次数。模拟题："模型承诺输出 JSON 后还需要 Pydantic 吗？" 应解释 JSON 语法不保证字段、类型或业务约束，且远端失败与版本差异仍可能发生。
