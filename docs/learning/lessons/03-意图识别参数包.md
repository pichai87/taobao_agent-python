# 第 3 课：让 Agent 先听懂问题

先记住一句话：**这一课的程序只判断你想做什么，还没有查询任何业务数据。**

> 阶段 4 更新：本课记录的是当时的单节点练习。现在 `taobao-intent` 直接调用同一个意图识别函数，正式 LangGraph 主图已放到 `workflow.py`，先执行 Intent，再执行 Supervisor。见第 4 课。

例如你问“昨天 GMV 比前天为什么下降？”，程序应先得到“这是归因问题、指标是 GMV、需要比较两个日期”。后续的 Supervisor 才决定交给哪个专家处理。

## 1. 本阶段解决的问题

把一句普通话变成固定字段的 JSON，供后续程序读取。原文 PDF 第 3、5 页要求 Intent Agent 识别问题类型、时间、指标和维度；模型失败时可用关键词与规则继续处理。当前程序只做这一步，不执行 SQL、查数或真正的归因。

## 2. 在整体 Agent 架构中的位置

它位于整个 Agent 的**入口**：

```text
你的问题 → Intent Agent 识别问题 → 将来由 Supervisor 选择专家
```

现在只实现了中间的识别部分。`taobao-agent` 是上一课的简单问答命令；`taobao-intent` 是本课用来查看识别结果的命令。LangGraph 仍只有一个工作节点，可暂时把它理解为“执行意图识别的步骤”。

## 3. 修改的文件、类和关键方法

| 文件 | 内容 |
| --- | --- |
| `src/taobao_agent/intent_agent.py` | `main()` 接收问题；`run_intent_once()` 运行一次识别；`IntentResult` 检查结果格式；`rule_fallback()` 在限流时识别少量固定句式 |
| `tests/test_intent_agent.py` | 用“假模型”检查代码，无需 Key 或费用 |
| `tests/fixtures/intent_golden.json` | 五道已写好预期答案的电商题 |
| `scripts/evaluate_intent.py` | 可选择用真实模型做五道题并对答案 |
| `pyproject.toml`、`README.md` | 注册命令并说明如何运行；没有新增依赖 |
| 学习路线、学习记录、本课 | 保存本阶段做了什么、验证了什么 |

## 4. 一条问题怎样走到结果

```text
问题字符串 + 今天的日期
  → main() 读取本次命令选用的 Key 和模型
  → run_intent_once() 把问题交给 LangGraph 的 intent 节点
  → 节点请模型输出 JSON
  → IntentResult 检查 JSON 的字段和日期
  → 终端打印检查过的结果
```

这里的 **State** 可以理解为图运行时传递的一张“小纸条”：先写入 `question`，节点执行后再写入 `result`。它只属于这一次提问，不会记住之前的聊天。

结果字段先看这几个：`intent_type` 是主问题类型；`metric_name` 是指标名；`curr` 是主日期；`prev` 是比较日期；`dimensions` 是“按行业”等分组要求。`secondary_intents` 表示同一句话还要求做第二件事。类型目前只允许取数、归因、查表结构、其他四种，这是**当前小范围实现**，不是原文所有可能类型。

## 5. 关键代码执行过程

`main()` 把“今天是哪天”交给识别函数，所以模型能把“昨天”换成具体日期。模型正常返回时，`IntentResult` 检查有没有缺字段、日期是否写成 `YYYY-MM-DD`、主意图是否属于允许的四类。Pydantic 是执行这些检查的 Python 库。

`metric_name=GMV` 只说明用户提到了 GMV；`metric_field` 是数据库字段名。项目还没有接入语义模型，不能确认字段名，因此现在只允许 `metric_field=null`。

如果模型调用遇到 429 限流，`run_intent_once()` 才尝试 `rule_fallback()`。规则目前只认识“昨天 GMV 多少”“昨天 GMV 比前天为什么下降”“按行业看昨天的 GMV”三类固定问法。命中时输出 `source=rule`；不认识时继续报告限流。正常模型结果标记为 `source=llm`。模型给出错误格式的 JSON 时不会用规则掩盖错误。

## 6. 设计原因与主要替代方案

- **原文要求**：一次模型调用得到意图参数；调用失败时可用规则降级。
- **必要工程补充**：提供明确的“今天”日期；检查 JSON；标明结果来自模型还是规则；没有字段依据时拒绝猜数据库字段。
- **目前的选择**：优先用模型理解自然语言。429 时只用少量明确规则，避免把没看懂的问题猜成某类。
- **替代方案**：所有问题都用关键词规则，代码会更简单，但很难覆盖不同说法和多任务问题。后续若业务需要，可以逐步扩充规则，不必现在写一大套。

## 7. 实际测试结果与已知限制

**为什么让你在终端运行 `taobao-intent`？** 本地假模型测试只说明代码能接收和检查预先准备的 JSON。终端命令则发送一次真实请求，检查 Plus Key、模型、提示词、日期解析和 JSON 校验能否连起来工作。它不会查询 GMV 数值，也不能用一次成功证明所有问题都识别正确。

你运行的命令中，`DASHSCOPE_API_KEY="$DASHSCOPE_PLUS_API_KEY"` 只在这一次命令里选用 Plus Key；`DASHSCOPE_MODEL=qwen-plus` 选择模型；`uv run taobao-intent` 启动本课程序；最后引号里的文字就是要识别的问题。Key 的内容不会写进项目文件。

你在 2026-10-23 运行“昨天 GMV 比前天为什么下降？”后，得到了 `intent_type=attribution`、`metric_name=GMV`、`curr=2026-10-22`、`prev=2026-10-21`、`metric_field=null`。这些字段与这个问题相符。输出中的 `confidence=0.95` 是模型自己给出的数字，**不等于已测得 95% 准确率**。那次运行发生在新增 `source` 字段之前；现在正常模型输出会多一个 `source=llm`。

| 你看到的字段 | 这次代表什么 |
| --- | --- |
| `intent_type=attribution` | 你在问“为什么下降”；这里只识别问题类型，还没有找下降原因 |
| `secondary_intents=[]` | 句子里没有第二个独立任务 |
| `metric_name=GMV`，`metric_field=null` | 认出了指标名，但还不知道它在数据库中的可靠字段名 |
| `time_label=昨天、前天` | 保留了你原话中的时间说法 |
| `curr=2026-10-22`，`prev=2026-10-21` | 按 2026-10-23 计算出的两天 |
| `scope=null`，`dimensions=[]` | 你没有指定范围，也没有要求“按行业”等分组 |

本地执行 `UV_CACHE_DIR=/private/tmp/taobao-agent-uv-cache uv run --locked --offline python -m unittest discover -s tests -v`：18 个测试通过，退出码 0。新增测试用“假 429”验证三个规则命中、未知问句继续失败、终端输出显示 `source=rule`，以及正常模型结果不会误标为规则。真实 429 降级还未由在线请求验证。

五道题的评测脚本目前**没有运行**。它固定参考日期来检查“昨天”，会发送五次真实请求；分数只能代表这五题，不能代表生产环境准确率。

## 8. 上下文工程、通信协议与评估

- **第九章，上下文工程**：只给模型当前问题、分类规则和今天的日期。现在不需要塞入 SQL 表结构或过去的聊天。
- **第十章，通信协议**：本课没有外部工具，也不需要 MCP 或 A2A。
- **第十二章，评估**：单元测试检查代码；你刚才的一次真实运行检查整条调用链；五道题的业务评测才开始估计识别效果。这三类证据不能互相代替。暂时不需要 LLM Judge 或大型公开基准。[Hello-Agents 第十二章](https://github.com/datawhalechina/hello-agents/blob/main/docs/chapter12/%E7%AC%AC%E5%8D%81%E4%BA%8C%E7%AB%A0%20%E6%99%BA%E8%83%BD%E4%BD%93%E6%80%A7%E8%83%BD%E8%AF%84%E4%BC%B0.md)提供了更完整的评估分类，本课只用其中最直接的“按预期字段对答案”。

## 9. Agent 岗位面试知识点

这些是**常见技术知识点，不是公开面经**。如果被问“为什么模型已经输出 JSON，还要检查？”可以用本项目回答：JSON 可能缺日期、把置信度写成 1.2，或编造数据库字段；程序必须拦住。若被问“为什么需要降级规则？”可回答：模型限流时，少数明确问题仍能处理；规则不认识时应报告失败，而不是猜。

## 10. 下一阶段前置条件

先确认你能用自己的话解释：终端命令验证了什么、`source` 表示什么、为什么 `confidence=0.95` 不是准确率。随后可选择运行五道题评测，找出容易识别错的问法；再进入 Supervisor 的简单路由。Supervisor 需要的 LangGraph 前置知识是“条件边根据 State 中的意图选择下一步”，届时只讲项目实际用到的部分。
