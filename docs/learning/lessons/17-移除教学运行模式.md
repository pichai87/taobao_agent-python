# 第 17 课：让合成数据退出主流程

先记一句话：**主命令现在只用已配置的 UCI 数据库查询数值；六笔合成订单只用来做离线测试。**

## 1. 本课解决的问题

第 12 课没有真实数据，因此临时加入了可切换的教学数据模式。现在已经有 UCI 公开数据，主流程仍同时判断 demo 和 UCI，导致 Query 的单日与两日代码都有两套数据源分支。你决定不再保留可运行的 demo 模式，本课据此删除它，并保留能验证 GMV 口径和 SQL 门禁的合成样例。

这是**用户提出的工程整理**，不是原文规定必须删除 demo。原文的 Query、Analysis、SQL Validator Gate 等目标仍需按后续课程逐步完成；UCI 数据也不能冒充淘宝百亿补贴数据。

## 2. 在整体架构中的位置

LangGraph 的节点和边没有变化：单日问题走 `Intent → Supervisor → Query`，两日问题走 `Intent → Supervisor → Query → Analysis`。本课改变的是 Query 节点内部可用的数据源：只有明确配置的 UCI SQLite 可以提供数值；没有配置时，Query 只说明找到的指标定义或缺失信息。

## 3. 修改的文件、类和关键方法

| 文件 | 当前作用 |
| --- | --- |
| `workflow.py` | `main()` 不再加载合成指标目录；`build_workflow()` 和 `run_workflow()` 不再传递 `demo_data`。旧 `TAOBAO_DEMO_DATA=1` 会明确报错。 |
| `query_agent.py` | `answer_query()` 与 `fetch_comparison()` 仅通过 UCI 工具取数；`QueryEvidence` 只接受 `source=uci`、`unit=pence`。 |
| `daily_metric_tool.py` | `make_daily_metric_tool()` 必须由程序传入 UCI 数据库路径；工具仍只对外开放指标名和日期。`DailyMetricValue` 只接受 UCI 来源及便士单位。 |
| `analysis_agent.py` | 移除不再可达的合成 GMV 回答分支，保留 UCI 两日比较和口径提醒。 |
| `demo_query_tool.py`、对应测试 | 原生产查询适配器及其专属测试删除；Git 历史保留旧实现。`examples/demo_shop.sql`、`examples/demo_metrics.json`、`test_demo_data.py` 和 `test_metric_sql.py` 继续验证合成 GMV 与 SQL 门禁。 |
| `test_workflow.py`、`test_daily_metric_tool.py`、`test_analysis_agent.py` | 将原先依赖 demo 运行模式的路径测试改为 UCI，继续覆盖结构化交接、工具权限和错误处理。 |

没有新增依赖，也无需安装数据库服务或 Navicat。

## 4. 当前调用链和数据流

以“2010-12-02 交易明细金额为什么比 2010-12-01 下降？”为例：

```text
main() 读取 TAOBAO_UCI_DB_PATH，加载 UCI 指标定义
  → run_workflow() 把 question 放进 WorkflowState
  → Intent 节点调用一次模型，IntentResult 转成 State.intent
  → Supervisor 选择 analysis，图先进入 Query
  → fetch_comparison() 对 prev、curr 各调用一次 query_daily_metric
  → query_uci_metric() 核对指标、数据库来源、日期及 SQL，再只读取数
  → 两个 DailyMetricValue 合成 QueryEvidence，写入 State.query_evidence
  → Analysis 从证据计算差额和变化率，写入 State.answer
  → WorkflowResult 返回 intent、next_expert、answer
```

**数据校验的位置**没有因移除 demo 而取消：模型输出进入 `IntentResult` 时检查格式；工具入口检查指标名与日期；执行前检查批准的指标定义和 SQL；Query 检查工具返回的日期、指标、来源和单位；Analysis 接收前再次把字典还原为 `QueryEvidence`。这些检查分别守住不同的数据边界。

## 5. 关键代码怎样执行

`TAOBAO_UCI_DB_PATH` 指向存在的 SQLite 文件时，主命令读取内置“交易明细金额”指标目录。`query_daily_metric` 的参数仍只有 `metric_name` 和 `business_date`；数据库路径由程序绑定，用户问题或未来的模型工具参数不能指定任意路径。底层继续使用固定 SQL 模板、后置校验和 SQLite 只读连接。

如果没有 UCI 路径，主命令不会因为自定义指标文件含有表名就直接查询数据库。旧命令若设置 `TAOBAO_DEMO_DATA=1`，会在创建模型前退出并提示该模式已移除。测试中的合成订单文件仍存在，但主命令不读取它们。

## 6. 为什么这样设计；其他做法

- **当前选择**：删掉已不用的运行分支，保留少量可核算样例。UCI 没有支付状态，合成订单仍能检验“只计已支付订单”的 GMV 规则。
- **没有选择**：把 demo 和 UCI 包装成复杂的数据源接口。当前只有一个可运行的数据源，先引入接口会增加理解和维护成本；以后接入真实业务库时，再依据实际差异设计接口。
- **后续整理**：`answer_query()` 和 `fetch_comparison()` 仍有部分相似的 UCI 前置检查和错误说明。下一课可针对这部分做小范围合并，不改变查询权限或返回口径。

## 7. 实际验证与限制

在项目根目录执行：

```bash
UV_CACHE_DIR=/private/tmp/taobao-agent-uv-cache uv run --locked --offline python -m unittest discover -s tests -v
```

**目的**：检查移除 demo 后，意图、图路由、UCI 单日及两日查询、工具参数、失败处理、合成 GMV 与 SQL 门禁是否仍满足已有断言。**实际结果**：67 个测试通过，退出码 0。测试数从第 16 课的 72 个减少，因为删除了不再存在的 demo 运行模式测试，并用 UCI 路径替换了相关交接测试。它不能证明真实模型总能识别问题，也不能证明完整归因已完成。

另用**固定输出的假模型**穿过本机已有的 UCI SQLite：2010-12-01 为 58960.79 英镑，2010-12-02 为 47748.38 英镑，回答为下降 11212.41 英镑、变化率 19.02%；退出码 0。这说明本次清理后本机真实数据取数和计算链仍工作，**没有发送在线模型请求**。第 15～17 课改动后的真实 Plus 模型在线复核仍待执行。

若要自己在线复核，可在已准备好 Plus Key 且本地数据库存在的终端运行：

```bash
env -u TAOBAO_METRIC_CATALOG_PATH -u TAOBAO_DEMO_DATA TAOBAO_UCI_DB_PATH=data/uci_online_retail/online_retail.sqlite DASHSCOPE_API_KEY="$DASHSCOPE_PLUS_API_KEY" DASHSCOPE_MODEL=qwen-plus uv run taobao-agent '2010-12-02 交易明细金额为什么比 2010-12-01 下降？'
```

**目的**：复核真实模型能否给出正确意图和两个日期，并穿过当前 UCI Query → Analysis 链。**预期**：`next_expert=analysis`，回答包含 11212.41 英镑与 19.02%。它会发送一次模型请求；即使成功，也只证明这一句的在线链路。`env -u TAOBAO_DEMO_DATA` 只是清除旧终端可能残留的设置，不会启用教学模式。

## 8. 本课涉及的知识

- **LangGraph**：没有新概念；State、节点和条件边均保持原样。本课只改变 Query 节点内部的数据源选择。
- **第九章，上下文工程**：模型只接收问题和意图识别规则；数据库路径和指标批准规则保留在程序配置里。
- **第十章，通信协议**：Query 仍由 Python 调用 LangChain 工具的 `.invoke()`，还不是模型自主 Tool Calling；不需要 MCP 或 A2A。
- **第十二章，评估**：合成订单用于可预期金额的单元测试；假模型加真实 UCI SQLite 是本地集成验证；真实 Plus 请求是另一个验证层次。三者不能互相替代。

## 9. Agent 岗位面试知识点

常见技术知识点：**为什么真实数据接入后仍保留合成测试数据？** 因为合成数据可精确控制边界情况和预期答案，能稳定发现计算或 SQL 门禁回归；公开 UCI 数据更适合验证真实文件导入和本地查询链。这是工程测试设计，并非某份公开面经的原题。
