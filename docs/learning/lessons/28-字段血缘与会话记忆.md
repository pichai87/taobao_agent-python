# 第 28 课：字段血缘与会话记忆

## 1. 解决的问题

**一句话**：用户可以问“GMV 从哪里来”，同一会话也能在下一次运行时把上一轮指标和日期作为省略问题的参考。

原文要求血缘图谱与会话记忆。本课的工程实现仅覆盖当前合成单表的字段血缘和本机 SQLite 会话；没有声称能追踪尚未接入的上游 ETL。

## 2. 架构位置与阅读顺序

先看 `lineage.py`，再看 `workflow.py` 中 `session_id` 分支，最后看 `intent_agent.py` 的 `session_context` 参数。`pyproject.toml` 和 `uv.lock` 新增 `sqlglot` 与 `langgraph-checkpoint-sqlite`。`tests/test_commerce_workflow.py` 有两项对应测试。

```text
血缘问题 → Intent(lineage) → Supervisor(lineage) → Query → 指标目录+MDL+SQL AST+实际字段 → 答案
多轮问题 → 指定 session_id → LangGraph SQLite checkpoint → 上轮确认的指标/日期
         → Intent 的上下文提示 → 本轮正常 Query/Analysis → 更新会话摘要
```

`State.session_context` 是给下一轮 Intent 使用的简短摘要；checkpoint 保存的是整个 LangGraph 状态。两者不能混同：有历史状态，不代表每个字段都适合直接放进模型上下文。

## 3. 数据流和关键方法

`describe_lineage(metric, database_path, knowledge)` 从受批准的指标定义生成标准 SQL，用 `sqlglot` 解析成语法树，核对表名和列名，并与实际 SQLite 字段交叉检查。确认后返回“CSV → 表字段 → SUM → 指标”的来源链。它不凭用户文本猜上游数据。

`run_workflow(..., session_id, checkpoint_path)` 用会话 ID 选择 LangGraph checkpoint。每轮结束时，只将已校验的 `IntentResult` 中指标、日期和维度写入 `session_context`。下一轮 `intent_node` 将这一摘要交给 `run_intent_once`，本轮明确给出的信息仍优先。不同 ID 之间隔离。对“那前一天呢？”这种明确省略问法，若上一轮只有一个日期，程序可直接从该日期减一天并复用指标；`source=rule` 表示该轮未靠模型猜日期。其他追问仍交给模型和结果校验。

终端例子：先执行 `uv run taobao-agent --session-id study '2026-10-22 GMV 多少？'`，再执行 `uv run taobao-agent --session-id study '那前一天呢？'`。目的是验证相同 ID 的两次运行可接续；预期第二次将上一轮信息送进 Intent。单次成功只证明这个问法，不能证明所有省略问法都识别正确。若没有 `--session-id`，运行仍是单轮。

## 4. 设计原因与替代方案

会话 checkpoint 是运行状态持久化；摘要是上下文工程，控制模型实际看到什么。把整个历史 JSON 无限制放入提示会增加噪声和成本。本课只保存单轮摘要，长任务压缩与删除策略留待 Harness/评测扩展。

血缘采用 AST 解析而不是只靠字符串匹配；当前只有一张表，完整图数据库没有收益。未来若接多表、ETL 和数据资产系统，才需要扩展为真正的跨任务图谱。

## 5. 验证与已知限制

本课初次执行 `PYTHONPYCACHEPREFIX=/private/tmp/taobao-pycache .venv/bin/python -m unittest discover -s tests -q`：当时 **34 项离线测试通过**。新增测试检查血缘答案仅引用批准的表字段，以及同一会话在新建图后仍可恢复摘要、不同 ID 不共享摘要。第 30 课真实模型冒烟发现“那前一天呢？”的模型日期字段互相矛盾并被校验拒绝；随后增加上述窄范围规则和离线回归，纠错过程见第 30 课。初次测试通过不代表真实模型追问可靠。

业务数据库与 checkpoint 数据库是两种用途：前者存合成交易数据，后者存程序会话状态。checkpoint 会保存完整 State，包括问题与回答，因此本地文件需要按实际数据敏感度保护。当前 `session_id` 只实现逻辑隔离，不是身份认证；Web 阶段必须把它绑定到经过认证的用户。血缘只证明当前受批准 SQL 的字段关系，不能证明真实生产环境的数据采集来源。

## 6. 相关学习和面试知识

Hello-Agents 第九章对应“Memory 与 Context 不同”：保留历史状态和选择本轮给模型看的内容是两步。第十章本课仍是进程内调用，无 MCP/A2A。第十二章要分开评估恢复成功率、跨会话泄漏和省略指代理解准确率。

常见面试问题（模拟）：为什么持久化 State 后还要组装上下文？因为 checkpoint 是完整运行记录，模型只应看到与当前问题相关且有权限的信息。为什么血缘要交叉校验实际字段？因为目录声明和数据库可能漂移。
