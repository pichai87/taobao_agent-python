# 电商数据分析 Agent 学习路线

## 依据与边界

- **原文依据**：用户提供的 27 页《淘宝百亿补贴数据分析助手 Agent 实战》PDF。正文和技术栈表确认：Intent Agent → Supervisor → Query / Analysis / Ops / Other；LangChain `create_agent` 用于 ReAct，LangGraph 用于多 Agent 编排；取数遵循 NL2MDL2SQL，并有 SQL Validator Gate、Harness、六层知识体系和 Web 平台。
- **必要工程补充**：使用 uv 管理 Python、虚拟环境和依赖；维护基础测试、教学文档和学习记录。原文没有指定 uv 或 Python 小版本。
- **可选优化**：只有在数据规模、性能或部署条件确有需要时，才接入 Hologres 加速、完整评测框架等能力。
- PDF 中部分插图为加载占位，Harness 具体限制、SQL 构建模式和沙箱安全模型等细节须在相应阶段重新核实，不以猜测填补。

## 阶段与依赖

| 阶段 | 最小交付 | 前置知识或依赖 | 状态 |
| --- | --- | --- | --- |
| 1 项目初始化 | Python/uv 配置、包结构、基础测试与学习文档 | 无 LangGraph 前置要求 | 已完成 |
| 2 最小可运行 Agent | 用户输入 → 一次 LLM 调用 → 结构化输出 | 单节点图所需的 State、节点、边和调用 | 已完成；Plus 真实调用成功一次，Turbo 曾遭遇 429 |
| 3 意图识别 | 意图、时间、指标和维度参数；少量业务评测样例 | 结构化输出及失败处理 | 单次真实识别成功；有限的 429 规则降级通过本地测试；五题在线评测待运行 |
| 4 Supervisor | 基于意图的简单路由与任务交接 | State 更新与交接边界；接入专家时再用条件边 | 主入口已接通 Intent → Supervisor；用户完成一次真实主流程调用；旧单节点图归档 |
| 5 专家 Agent | 从一个真实用例开始逐个加入专家 | 已验证的路由和专家输入输出协议 | Other 寒暄已有一次真实运行；Query 的第一步已接入，Analysis、Ops 尚未执行 |
| 6 工具与业务执行 | 按需加入检索、SQL 构建、查询与分析工具 | 首次生成业务 SQL 前须有最小表/字段/指标口径与规则；真实查询前须有基本只读限制和校验 | 第一小步完成：Query 调用本地 `search_metrics`；真实指标目录、SQL 和数据源待接入 |
| 7 Harness 与安全 | 执行预算、错误处理、SQL Validator Gate 和必要恢复 | 已有可观察的工具执行路径 | 第一小步完成：指标查找的超时/断线边界；SQL Gate、预算与恢复待实际执行路径 |
| 8 知识与上下文 | 按需求扩展 MDL、片段、规则、血缘、指标注册与会话记忆 | 已识别真实取数或归因的知识缺口 | 第一小步完成：从可选 JSON 文件加载最小指标目录；真实 MDL、规则、RAG、记忆待接入 |
| 9 Web | FastAPI、React 和流式展示逐步接入 | CLI 路径的输入输出与错误契约稳定 | 待开始 |
| 10 评估扩展 | 扩充 Golden Dataset、回归、质量和成本指标 | 每项行为已有小型验证 | 待开始 |

阶段编号是交付顺序，不允许跳过真实依赖。第 6 阶段的首个工具先完成“查指标”的调用边界；在生成业务 SQL 之前，还需真实指标语义资料与基本 SQL 安全检查。第 8 阶段才扩展完整知识体系。原文所列 WrenAI、TisPlus3、LightRAG、ODPS、Hologres 等不会仅为演示工具调用而安装。

第 7 阶段先保护已存在的查指标调用。PDF 未给出可核实的具体超时/重试预算，当前不擅自设定；SQL Validator Gate 会随真实 SQL 构建与执行路径一起设计、验证。

第 8 阶段先让 Query 使用可追溯的外部指标定义文件，作为后续接入真实 MDL/指标注册资料的过渡。文件格式校验不等于业务审核；只有拿到可信表结构和过滤口径后，才能继续 SQL 构建。RAG 在规则、SQL 片段和血缘知识需要动态检索时再引入。

## 按需学习映射

- **LangGraph 基础**：阶段 2 的 State/节点/边，阶段 4 的两节点交接，阶段 5 接入第一个专家时再使用条件边。项目文档只解释所用 API 在调用链中的作用。
- **Hello-Agents 第九章，上下文工程**：阶段 2 的提示输入开始接触；阶段 5 的专家只读取必要 State，阶段 8 的动态知识召回是重点。
- **第十章，智能体通信协议**：阶段 4/5 讲同进程交接；阶段 6 讲工具调用与普通函数。仅有明确外部协议需求时才引入 MCP/A2A。
- **第十二章，智能体性能评估**：阶段 3 建意图样例；阶段 5 验证专家分支与交接，阶段 6/7 验证工具、SQL 与失败行为，阶段 10 扩充为系统评测。
- **第十一章，Agentic RL**：当前路线不涉及模型训练，暂不引入。
