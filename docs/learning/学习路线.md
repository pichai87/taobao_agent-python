# 电商数据分析 Agent 学习路线

## 依据与边界

- **原文依据**：用户提供的 27 页《淘宝百亿补贴数据分析助手 Agent 实战》PDF。正文和技术栈表确认：Intent Agent → Supervisor → Query / Analysis / Ops / Other；LangChain `create_agent` 用于 ReAct，LangGraph 用于多 Agent 编排；取数遵循 NL2MDL2SQL，并有 SQL Validator Gate、Harness、六层知识体系和 Web 平台。
- **必要工程补充**：使用 uv 管理 Python、虚拟环境和依赖；维护基础测试、教学文档和学习记录。原文没有指定 uv 或 Python 小版本。
- **可选优化**：只有在数据规模、性能或部署条件确有需要时，才接入 Hologres 加速、完整评测框架等能力。
- PDF 中部分插图为加载占位，Harness 具体限制、SQL 构建模式和沙箱安全模型等细节须在相应阶段重新核实，不以猜测填补。

## 阶段与依赖

| 阶段 | 最小交付 | 前置知识或依赖 | 状态 |
| --- | --- | --- | --- |
| 1 项目初始化 | Python/uv 配置、包结构、基础测试与学习文档 | 无 LangGraph 前置要求 | 已完成 |
| 2 最小可运行 Agent | 用户输入 → 一次 LLM 调用 → 结构化输出 | 单节点图所需的 State、节点、边和调用 | 已完成；Plus 真实调用成功一次，Turbo 曾遭遇 429 |
| 3 意图识别 | 意图、时间、指标和维度参数；少量业务评测样例 | 结构化输出及失败处理 | 单次真实识别成功；有限的 429 规则降级通过本地测试；五题在线评测待运行 |
| 4 Supervisor | 基于意图的简单路由与任务交接 | State 更新与交接边界；接入专家时再用条件边 | 主入口已接通 Intent → Supervisor；用户完成一次真实主流程调用；旧单节点图归档 |
| 5 专家 Agent | 从一个真实用例开始逐个加入专家 | 已验证的路由和专家输入输出协议 | Other 寒暄与合成 Query 各有一次真实模型运行；Query 还可查询本地 UCI 公开数据；Analysis、Ops 尚未执行 |
| 6 工具与业务执行 | 按需加入检索、SQL 构建、查询与分析工具 | 首次生成业务 SQL 前须有最小表/字段/指标口径与规则；真实查询前须有基本只读限制和校验 | Query 已接合成数据及 UCI 公开数据的本地只读工具；外部业务数据库及更多问法待实现 |
| 7 Harness 与安全 | 执行预算、错误处理、SQL Validator Gate 和必要恢复 | 已有可观察的工具执行路径 | 指标查找错误边界、固定模板 SQL 后置门禁与教学数据库只读连接已接通；任意 SQL 与真实数据权限待实现 |
| 8 知识与上下文 | 按需求扩展 MDL、片段、规则、血缘、指标注册与会话记忆 | 已识别真实取数或归因的知识缺口 | 第一小步完成：从可选 JSON 文件加载最小指标目录；真实 MDL、规则、RAG、记忆待接入 |
| 9 Web | FastAPI、React 和流式展示逐步接入 | CLI 路径的输入输出与错误契约稳定 | 待开始 |
| 10 评估扩展 | 扩充 Golden Dataset、回归、质量和成本指标 | 每项行为已有小型验证 | 待开始 |

阶段编号是交付顺序，不允许跳过真实依赖。第 6 阶段的首个工具先完成“查指标”的调用边界；在生成业务 SQL 之前，还需真实指标语义资料与基本 SQL 安全检查。第 8 阶段才扩展完整知识体系。原文所列 WrenAI、TisPlus3、LightRAG、ODPS、Hologres 等不会仅为演示工具调用而安装。

第 7 阶段先保护已存在的查指标调用。PDF 未给出可核实的具体超时/重试预算，当前不擅自设定；SQL Validator Gate 会随真实 SQL 构建与执行路径一起设计、验证。

第 8 阶段先让 Query 使用可追溯的外部指标定义文件，作为后续接入真实 MDL/指标注册资料的过渡。文件格式校验不等于业务审核；只有拿到可信表结构和过滤口径后，才能继续 SQL 构建。RAG 在规则、SQL 片段和血缘知识需要动态检索时再引入。

**第 9 课是跨阶段的数据前置工作，并非上表的“阶段 9 Web”**：项目尚无真实数据，先加入 6 笔明确标为合成的订单、一份可被现有加载器读取的指标文件，以及固定口径的本地核算测试。下一课优先让日期、支付状态和聚合规则成为可校验的指标契约，再考虑查询执行与 SQL Gate。公开数据随后单独接入：候选包括 [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail) 和 [Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)；选择时先核对许可、字段语义和取消/支付口径，再建立导入与业务评测样例。两者都不能直接提供淘宝补贴字段。Web 仍待 CLI 的查询结果与错误契约稳定后开始。

**第 10 课已完成指标契约的第一步**：样例 JSON 中可选的 `calculation` 现在包含 `sum`、支付日期、一个等值条件和单位，由 Pydantic 在模型调用前校验。旧四字段文件继续可读。它尚未验证真实库的字段权限，也不生成 SQL。下一课可在已有合成表上设计限定范围的只读查询与 SQL Validator Gate，再考虑接入 Query。当前使用 Python 自带 SQLite；无需安装数据库服务或 Navicat。若未来确需外部数据库，将在相应课程提前说明安装与连接要求。

**第 11 课已完成固定模板的 SQL 构建与后置校验**：只支持合成 GMV 所需的 `SELECT SUM`，日期和状态作为绑定参数；门禁核对完整 SQL、参数和批准的表字段。测试在内存 SQLite 上得到已知结果，但主图没有调用新模块。下一步为 Query 接入受控的本地数据查询路径，同时保证每次执行前经过门禁；连接外部数据库前仍需核实数据来源、权限和口径。

**第 12 课已把教学数据查询接入现有 Query 节点**：只有 `TAOBAO_DEMO_DATA=1` 才自动加载项目的合成指标目录，并调用本地函数完成建库、只读限制、SQL 构建、门禁和执行。当前仅回答单日无分组 GMV，普通模式维持原状。测试通过假模型验证主图与 CLI 路径；用户随后完成一条真实模型查询。外部数据库软件需求会在相应课程提前说明。

**第 12 课的真实模型补充验证**：用户已用 Plus Key 查询 `2026-10-22 GMV`，得到 `next_expert=query`、`answer=教学合成数据：2026-10-22 的 GMV 为 200.00 元。`。这只证明该固定问法的一次在线链路。

**第 13 课改为按完整业务能力推进**：从 UCI 官方 Online Retail Excel 导入本地 SQLite，配置独立的“交易明细金额”口径，复用现有 Query、SQL 构建与门禁，完成一条可复核的公开数据查询。原始和导出数据留在被忽略的 `data/`，仓库只保存导入程序与规则。2010-12-01 的 58960.79 英镑已与独立扫描 Excel 的结果核对；模型对这句新问法的在线识别待验证。该数据无支付状态，不得标为已支付 GMV。仍无需安装数据库服务或 Navicat。后续可在这条可靠数据链上逐步做比较、维度或 Analysis；RAG 在需要动态召回知识时再接入。

## 按需学习映射

- **LangGraph 基础**：阶段 2 的 State/节点/边，阶段 4 的两节点交接，阶段 5 接入第一个专家时再使用条件边。项目文档只解释所用 API 在调用链中的作用。
- **Hello-Agents 第九章，上下文工程**：阶段 2 的提示输入开始接触；阶段 5 的专家只读取必要 State，阶段 8 的动态知识召回是重点。
- **第十章，智能体通信协议**：阶段 4/5 讲同进程交接；阶段 6 讲工具调用与普通函数。仅有明确外部协议需求时才引入 MCP/A2A。
- **第十二章，智能体性能评估**：阶段 3 建意图样例；阶段 5 验证专家分支与交接，阶段 6/7 验证工具、SQL 与失败行为，阶段 10 扩充为系统评测。
- **第十一章，Agentic RL**：当前路线不涉及模型训练，暂不引入。
